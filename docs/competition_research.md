## 6. Key Judging Criteria Across Runway Competitions

Based on the official 2026 API Hackathon page, Runway judges evaluate on:

### **Creativity**
"Does your project solve a real problem or explore an interesting use case?"
- **Signal:** Novel application domains (education, healthcare, enterprise, accessibility)
- **Signal:** Unexpected creative combinations (not just "pretty video")
- **Anti-signal:** Recreating existing tools that already exist

### **Technical Depth**
"How well does the project leverage Runway's API? Does it go beyond basic usage?"
- **Signal:** Complex orchestration of multiple API calls
- **Signal:** Building stateful systems (memory, iteration, feedback loops)
- **Signal:** Custom integration with other AI services or APIs
- **Anti-signal:** Single API call → output

### **Impact**
"Could this project be used by real users or customers? Could it become a real product?"
- **Signal:** Clear user journey and value proposition
- **Signal:** Scalability considerations (not just a prototype)
- **Signal:** Existing user base or clear market demand
- **Anti-signal:** "Cool demo" but no real-world application

### **Polish**
"Is your project a working demo, not just a concept? Does it feel end-to-end?"
- **Signal:** Polished UI/UX (if relevant to project)
- **Signal:** Handles edge cases and errors gracefully
- **Signal:** Complete workflow from input to output
- **Anti-signal:** Brittle, breaks on unexpected input

## 8. Strategic Insights for May 2026 Hackathon

### What Wins at Runway Competitions:
1. **Agentic systems** (not one-shot generation)
   - Multi-step decision making
   - Feedback loops and iteration
   - Real-time responsiveness

2. **Cross-domain innovation**
   - Apply video generation to unexpected fields (medical, education, enterprise)
   - Combine Runway with other APIs (LLMs, music, 3D engines)
   - Build for real workflows, not toy examples

3. **Developer-first tools**
   - Tools that other developers would want to use
   - Good documentation/example integrations
   - Extensible architecture

4. **End-to-end workflows**
   - Handle the full user journey
   - Polish the interface (even if web-based)
   - Deal with edge cases

### What Doesn't Win:
- Pure aesthetic/art projects without use case
- Single API call outputs
- Unpolished prototypes
- "Showcase feature X" rather than "solve problem Y"
